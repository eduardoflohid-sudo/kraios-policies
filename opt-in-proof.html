Single recipient / self-use

SMS Opt-In Configuration Evidence

The Kraios Development Alerts operator explicitly requested software-development SMS notifications to their own number and configured the sole destination through a private GitHub Actions repository secret named SMS_TO_NUMBER.

How consent is recorded

There is no public registration form or keyword campaign. The operator opts into the service by directly setting their own SMS destination in the private notifier configuration. The outbound SMS code obtains one destination from that secret. No customer subscription database or marketing list is used. Twilio sending is disabled by default and is only enabled by the operator after sender approval.

Explicit single-recipient enrollment and SMS consent language

The sole operator requests these text messages and opts in by placing their own mobile number in the private SMS_TO_NUMBER repository secret. This is an owner-initiated application setting, not a public signup form, website checkbox, or keyword campaign. This is the consent language documenting the program:

I agree to receive recurring automated SMS from Kraios Development Alerts about software-development progress, GitHub pull requests, test results, and code reviews at the number I designate in my private configuration. Message frequency varies; the configured default is up to 12 regular notifications per day plus a possible limit notice. Message and data rates may apply. Reply STOP to unsubscribe or HELP for assistance after messaging is activated.

Program messages and control

Messages report GitHub pull requests, CI test results, AI coding progress and software-development interruptions. The recipient controls whether messages are enabled and may disable SMS through private configuration. After Twilio activation, Twilio sender opt-out handling will also be enabled for STOP and HELP.
